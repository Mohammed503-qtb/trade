## A. استراتيجية البيئة والتشغيل (قرارات D-01، D-12، D-13، D-15)

### A.1 الطوبولوجيا المنطقية مقابل طوبولوجيا التشغيل
- **المنطقية (كما في §47):** حزم منفصلة بمسؤوليات صارمة — الحدود تُفرض آليًا
  بـ **import-linter** (عقود `contracts` في `pyproject.toml`): ممنوع `services.execution`
  يستورد من `services.analysis`، ممنوع `pine/*` من أي منطق، ممنوع `packages.features`
  يستورد خدماتًا... إلخ. كسر عقد = فشل `make gate`.
- **التشغيل في sandbox:** عمليات قليلة (تجميع D-12):
  1. `engine-api` (FastAPI: webhook + حالة + قراءة)
  2. `engine-worker` (خط الأنابيب: ingestion→state→analysis→fusion→scenarios→risk)
  3. `engine-replay` (تُطلق عند الطلب: إعادة/اختبارات)
  4. `nats-server` (ثنائية رسمية user-space)
  5. `postgres` (embedded binaries user-space)
  6. `minio` (ثنائية رسمية user-space)
  7. تطبيق Next (موجود — لوحة + حافة webhook)
- **التشغيل على الخادم الهدف:** نفس الخدمات عبر `infra/docker-compose.yml`
  (الملف يُؤلَّف من المرحلة 0 كمواصفة قانونية ويُختبر فور توفر Docker حقيقي).

### A.2 مدير العمليات المحلي (sandbox)
`infra/local/supervisor.py` (Python، لا تبعيات خارج stdlib):
- يقرأ `infra/local/services.yaml` (الأوامم، المنافذ، فحوص الصحة، ترتيب الإقلاع).
- إقلاع متدرج: postgres → nats → minio → migration → worker → api.
- إعادة تشغيل الأبناء عند الفشل، سجل موحد، أوامر: `start/stop/status/health`.
- **الإدماج مع المنصة (D-15):** خدمتان wrapper تحت `mini-services/` تحملان
  `package.json` بـ `dev: python infra/local/supervisor.py run …` — فتدhiveهما
  منصة الـsandbox عبر `dev.sh` ويبقيان عبر إعادة الإقلاع.

### A.3 المنافذ (كلها داخلية، لا تكشف خارجيًا إلا عبر Next)
| الخدمة | المنفذ |
|---|---|
| Next (لوحة + حافة) | 3000 (تديره المنصة) |
| engine-api (FastAPI/uvicorn) | 4001 |
| postgres | 5543 (غير القياسي تفاديًا للتصادم) |
| nats client / monitor | 4222 / 8222 |
| minio api / console | 9100 / 9101 |

### A.4 الأسرار والإعدادات
- `.env` (مُتجاهَل في git) + `.env.example` موثّق بكل المتغيرات.
- مفاتيح: `ENGINE_ENV=dev|target`، `DATABASE_URL`، `NATS_URL`، `S3_*`،
  `TV_WEBHOOK_SECRET`، `BINANCE_*`. لا سرّ في الشيفرة أبدًا (§37.1).
- **تنبيه أمني قائم:** توكن GitHub الذي شاركه المالك في المحادثة يجب **إبطاله
  وتدويره** فور انتهاء الحاجة إليه (موثّق في §6 من plan_review).

### A.5 حزم المخططات أولًا (مبدأ الترميز)
`packages/schemas`: نماذج **Pydantic v2** هي مصدر الحقيقة الوحيد لكل الرسائل
(§32) والحقول JSONB. تصدير آلي: JSON Schema → `schemas/generated/` + صفحة
توثيق. أي رسالة على NATS بلا مخطط مُصدَّر = فشل بوابة.

**انحرافات موثّقة عن §47:** (1) الجذر `engine/` داخل sandbox لا جذرًا مستقلًا —
قيد المنصة (D-13). (2) `apps/dashboard` = تطبيق Next الموجود خارج `engine/` —
توافق §5.7 (React+TS) مع قيد المسار `/` الوحيد. (3) `services/macro` يُدمج
مبدئيًا في `market_state` كوحدة فرعية (نوافذ الحظر فقط داخل MVP) — الحزمة
المستقلة عند توسيعه بعد MVP. كلها صقل تشغيلي لا مساس بالحدود.

## E. استراتيجية الاختبار (مقسمة على المراحل)
- **Unit/fixtures (كل كاشف من المرحلة 1):** golden inputs/outputs من §38.1 + نسب غامضة تبقى مرشحة.
- **Property (من المرحلة 0):** hypothesis لثوابت §38.2 + حتمية seed + حدود درجات — تعمل في كل `make gate`.
- **Replay (المرحلة 9):** نفس البيانات/الإصدار ⇒ نفس النتائج؛ نوافذ قراءة متحركة تمنع المستقبل معماريًا لا بالتزام.
- **Integration (تراكمية من المرحلة 1):** feed→ingestion→DB→NATS→analysis→scenario→risk→execution-mock (§38.4) على عينة صغيرة.
- **Chaos (من المرحلة 8):** حقن فشول §38.5 كأعلام تشغيل — النتيجة المقبولة دائمًا: تدهور آمن (SAFE/LOCKED) لا تداول أعمى (§49).
- **الوكيل الآلي للوحة (المرحلة 10):** تحقق E2E بصري وتفاعلي.

## F. استراتيجية Git والنسخ
- **فروع:** `main` محمي؛ عمل بفرع `phase/N-task` — دمج بـ PR محلي بعد بوابة المهمة.
- **رسائل:** Conventional Commits بالعربية المساعدة بالإنجليزية: `feat(ingestion): مصنف جودة الشرائح (§7.4)`.
