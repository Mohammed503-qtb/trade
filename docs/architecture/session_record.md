## الجلسة 0 — جلسة التأسيس: عائق استلام Master Plan.md

### الحدث
كُلّفت في هذه الجلسة بأربع مراحل صارمة: فهم عميق لـ `Master Plan.md`، ثم تحليل نقدي
(`plan_review.md`)، ثم خطة تنفيذ (`build_plan.md`)، ثم عرضهما وانتظار إشارة البدء.

**النتيجة: الملف المصدر لم يصل إلى نظام الملفات.**

### الدليل على عدم الوصول (فحص منهجي، لا انطباع)
1. `/home/z/my-project/upload/` فارغ تمامًا (`ls -la` لا يُظهر سوى `.` و `..`).
2. بحث شامل باسم الملف (`**/*Master*`) عبر كامل `/home/z` — لا نتيجة.
3. بحث عن أي ملف `.md` حديث التعديل خارج `node_modules` — لا شيء سوى `download/README.md` (ملف القالب الافتراضي).
4. سجل git يحتوي على `Initial commit` فقط — لا أثر لاستلام الملف في أي جلسة سابقة.

### القرار المُتخذ (ADR-001)
**رفض اختلاق تحليل.** لن يُكتب `plan_review.md` ولا `build_plan.md` قبل وصول النص الفعلي
للخطة. كتابة "تحليل نقدي" لمستند لم يُقرأ هي غش معماري يُدمّر الغاية الكاملة من
بروتوكول المراحل الأربع: المستخدم يقيس جودة التفكير *في خطته هو*، لا قدرة على توليد
نصوص عامة. البديل المرفوض: تخمين بنية الخطة من اسمها ومقتطفات رسالة التكليف ثم البناء
على التخمين — مرفوض لأن أي قرار مبني على افتراض غير متحقق سيتسرب لاحقًا إلى الكود
والبنية ويكلّف إعادة بناء كارثية.

**الحالة:** متوقف عند عائق حقيقي (المطلوب رقم 4 في رسالة التكليف لم يتحقق).
**المطلوب لإزالة العائق:** إعادة إرفاق `Master Plan.md` أو لصق محتواه مباشرة في المحادثة.

### تدقيق البيئة (أُنجز في هذه الجلسة استعدادًا — مهم بغض النظر عن محتوى الخطة)

اكتُشف **قبل** قراءة الخطة تصادم محتمل بين افتراضاتها التحتية (يُستدل عليها من نص
التكليف: Docker Compose، NATS، Postgres، Redis) وبين واقع بيئة التنفيذ:

| المورد | الحالة | الأثر على خطة التنفيذ |
|---|---|---|
| Docker / Compose | **غير موجود إطلاقًا** | استراتيجية "Docker Compose" الحرفية غير قابلة للتنفيذ هنا؛ سيتطلب الأمر "تكيف نشر" يوثَّق صراحة |
| NATS Server | غير مثبت، **لكن** الشبكة متاحة (github 200) ويمكن تنزيله كثنائية Go مستقلة | بديل واقعي: NATS كثنائية مستقلة تُدار كـ mini-service |
| PostgreSQL / Redis | غير مثبتة؛ `apt-get` موجود لكن الجلسة ليست root (uid=1001) | قرار معلق: بدائل محمولة أو استخدام المتاح (Prisma/SQLite مهيأ مسبقًا) — يُحسم بعد قراءة متطلبات الخطة الفعلية |
| Node / Bun / Python | Node 24.21، Bun 1.3.14، Python 3.12 + pip | كافية لخدمات TypeScript بفئة جودة إنتاج |
| الموارد | 4.1GB RAM، 2 نواة، 8GB قرص حر | يفرض حدًا على عدد العمليات المتزامنة وأحجام البيانات في بيئة التطوير |
| البوابة | منفذ خارجي واحد عبر Caddy؛ خدمات داخلية تُوصل عبر `?XTransformPort=` | أي معمارية services يجب أن تراعي هذا القيد في الواجهة والاتصال |

**هذه النتائج ستُدمج في `plan_review.md` كقسم "قيود بيئة التنفيذ" فور وصول الخطة.**

## الجلسة 0.1 — بناء طبقة موثوقية الاستلام (ADR-002)

طلب المستخدم ضبط مجلدات الرفع/الاستقبال لتكون قابلة للقراءة والكتابة. الفحص كشف أن
`upload/` كان 777 أصلًا — الخطر الحقيقي ليس الصلاحيات بل **فقدان الملفات** (المجلد
مُدار من المنصة بملكية root وتاريخ epoch، وقد يُفرَّغ).

### ما بُني
1. **`received/`** — صندوق استقبال دائم (777) لا يمسه أحد.
2. **مراقب داخل خادم dev نفسه** — `src/instrumentation.ts` (ملف دخيل رفيع) يستورد
   ديناميكيًا `src/lib/upload-watcher.ts` داخل حرس `NEXT_RUNTIME === "nodejs"`.
   يفحص `upload/` كل ثانية؛ عند استقرار حجم ملف عبر استطلاعين ينسخه فورًا إلى
   `received/` باسم آمن ضد التصادم، ويسجل في `received/.arrival-log`.
   عمر المراقب = عمر الخادم → يعود تلقائيًا مع كل إقلاع حاوية.
3. نسخة bash احتياطية: `.zscripts/upload-watcher.sh` (تشغيل يدوي فقط).
4. `allowedDevOrigins: ["*.space-z.ai"]` في next.config.ts — يحسم تحذير الأصل المتقاطع.

### اختبارات نهاية-إلى-نهاية (نجحت كلها)
- ملف بمسافة في الاسم + محتوى عربي وصل `upload/` → لقطة في `received/` خلال ~2 ثانية
  مع سطر SNAPSHOT موثق في السجل، والأصل بقى سليمًا (غير تدميري).
- حذف الأصل لا يمس اللقطة. `bun run lint` نظيف. الخادم 200 والمراقب حي داخل العملية.

### اكتشافات بيئية حاسمة (تُبنى عليها خطة التنفيذ لاحقًا)
| الاكتشاف | الأثر |
|---|---|
| العمليات الخلفية التي يطلقها الوكيل تُقتل بين أوامر الأدوات؛ `nohup` و`setsid` المفرد لا ينفعان | أي خدمة أطلقها يدويًا يجب أن تُطلق بنمط **double-fork** (اختُبر: نجح) أو تُضمّن داخل عملية تديرها المنصة |
| العمليات المُدارة من المنصة (خادم dev عبر `.zscripts/dev.sh`) هي الوحيدة المضمونة البقاء | خادم dev هو المضيف الموثوق لأي منطق دائم (وضع المراقب فيه) |
| `instrumentation.ts` بلا استيرادات ساكنة لـ `node:*` — الاستيراد الساكن يُفسد بناء edge ويمنع التنفيذ كليًا | النمط الإلزامي: ملف دخيل رفيع + استيراد ديناميكي محروس |
| تعديل `next.config.ts` يعيد تشغيل خادم dev تلقائيًا وبنظافة | رافعة موثوقة لتحميل أي تغيير bootstrap-level |
